Stacks — Event-Driven Data Flow (Revised)

No polling anywhere. Events propagate end-to-end.

Full Event Chain
Docker Engine
Container lifecycle event fires (start, stop, die, restart)
▼ docker events stream
Agent
GET /stacks/events (SSE) — Agent subscribes to docker events, maps container → stack via compose project label, emits stack status snapshots on change
▼ SSE stream (persistent connection per host)
Worker
StackStatusCollector — Connects to each agent's /stacks/events, upserts stack_status table on each event, triggers NOTIFY stack_change
▼ PostgreSQL NOTIFY
Server (SSE)
GET /api/stack-status — Listens for stack_change NOTIFY, broadcasts current stack status to all connected browsers
▼ SSE stream
Browser
useStackStatus hook — Receives live updates, renders container status in StackRow + StackDetail

Key Design Decisions

Full snapshot per event

Agent sends ALL containers for the affected stack on each event — not deltas. Worker can upsert the whole row atomically. Simple, idempotent, no ordering issues.

Stack identification via compose label

Docker Compose sets com.docker.compose.project on every container. Agent uses this to map events → stacks. No guessing.

Reconnection with initial snapshot

When worker connects (or reconnects) to agent SSE, agent sends current status of ALL stacks immediately. No missed events during downtime.

Deploy pipeline also triggers NOTIFY

When a deploy completes, the pipeline updates deploy_history AND triggers NOTIFY stack_change. UI sees sync status update immediately — no waiting for the next Docker event.
